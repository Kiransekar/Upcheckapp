## Shared contract — Tasks API (Agents 5 and 6 build to this, exactly)

```ts
type TaskScope = 'farm' | 'personal';

interface Task {
  id: string; farmId: string; pondId: string | null; cropId: string | null;
  title: string; description: string | null;
  status: 'open' | 'in_progress' | 'done' | 'verified' | 'cancelled';
  priority: 'low' | 'medium' | 'high';
  type: 'FEED' | 'WATER_TEST' | 'SAMPLING' | 'AERATOR_CHECK' | 'MORTALITY_CHECK' | 'HARVEST_PREP' | 'OTHER';
  dueDate: string | null;            // 'YYYY-MM-DD'
  timeWindowStart: string | null; timeWindowEnd: string | null;  // 'HH:mm'
  scope: TaskScope;
  assigneeIds: string[];             // [] means EVERYONE in scope (farm-wide, or pond-wide when pondId is set)
  createdById: string | null;
  completedAt: string | null; verifiedAt: string | null; verifiedById: string | null;
  isTemplate: boolean;               // true = a recurrence template, never shown as a to-do
  recurrenceRule: string | null;     // 'FREQ=DAILY' | 'FREQ=WEEKLY;BYDAY=1'
  recurrenceUntil: string | null;    // 'YYYY-MM-DD' or null = forever
  parentTaskId: string | null;       // instance -> its template
  createdAt: string; updatedAt: string;
}
```

Routes:
- `POST /tasks` — body `{ farmId, title, description?, pondId?, cropId?, type?, priority?, dueDate?, timeWindowStart?, timeWindowEnd?, scope?, assigneeIds?, recurrence?: { freq: 'daily' | 'weekly', byWeekday?: 0-6, until?: 'YYYY-MM-DD' } }`. `recurrence` present ⇒ creates a **template** (`isTemplate: true`) and returns it; instances are materialised on read.
- `GET /tasks?farmId=&status=&assignedToId=&scope=&dueBefore=` — visible farm tasks, templates excluded.
- `GET /tasks/mine` — `Task[]` across all accessible farms: tasks assigned to me, plus unassigned (`assigneeIds: []`) farm/pond tasks in my scope, plus my own personal tasks. Shape unchanged from today so `/team/overview` keeps working.
- `GET /tasks/templates?farmId=` — the recurrence templates, so a manager can edit or stop a daily task.
- `PATCH /tasks/:id`, `POST /tasks/:id/complete`, `POST /tasks/:id/verify`.
- `DELETE /tasks/:id?series=true` — deletes a template and its future, not-yet-completed instances.

Rules:
- **Personal tasks** (`scope: 'personal'`) are created by anyone with `READ`, are always assigned to the creator alone, and are visible **only** to their creator. They can never be assigned to someone else — the server rejects `scope: 'personal'` with an `assigneeIds` that is not exactly `[creator]`.
- **Farm tasks** (`scope: 'farm'`) require `WRITE_MANAGEMENT` (owner/manager) to create or to assign.
- Every id in `assigneeIds` must be an **active member of that farm**; if `pondId` is set, the assignee must also have access to that pond. Reject otherwise — do not silently drop.
- **Pond scoping is enforced on read**: a pond-scoped worker must not see tasks for ponds outside `getAccessiblePondIds`. This is a live authorization hole today (`tasks.service.ts` filters by farm only) — close it.
- **Recurrence is template + instances.** On any read that covers a date range, materialise the missing instances for each active template from the later of (template start, today − 7 days) through today, idempotently (unique on `parent_task_id + due_date`). No cron: there is no scheduler in this backend and adding one is out of scope.
- The UI distinguishes **assigned to me by someone else** (`createdById !== me`) from **my own** (`createdById === me`). No extra column — derive it.
